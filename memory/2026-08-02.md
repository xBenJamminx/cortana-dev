# 2026-08-02

## Fixed: Cortana refusing to save API keys

**Reported:** Ben said Cortana would not save keys for him.

**Root cause:** The Jul 28 commit `b8a6c99` ("docs: modernize Cortana runtime
for Hermes") rewrote the docs from openclaw to Hermes but changed no code.
Three dead ends resulted, and together they left no working route to storing
a key:

1. Docs said keys go in `~/.hermes/.env`. All seven `_load_env()` copies in
   `scripts/*.py` still read `~/.openclaw/.env` only.
2. `AGENTS.md:53` pointed at `lib/alerting.py` for the `_load_env()` pattern.
   That file has `_load_state()`, never had `_load_env()`.
3. `CLAUDE.md`'s task router sends auth work to `context/auth.md`. The whole
   `context/` directory has never existed in this repo.

The `.gitignore` rules and the `detect-secrets` pre-commit hook were **not**
the problem. Those correctly block secrets from entering the repo and were
left untouched.

**Fix (commit `09b0604`, branch `claude/cortana-key-saving-ie4p92`):**

- Added `lib/env.py`, the canonical loader the docs claimed existed. Checks
  `~/.hermes/.env` then `~/.openclaw/.env`; first existing file wins; returns
  the loaded path or `""`.
- Gave all seven inline `_load_env()` copies the same fallback, so scripts run
  on migrated and unmigrated boxes.
- Repointed `AGENTS.md`, `AGENTS - Cortana.md`, `TOOLS.md` at `lib/env.py`.
- Wrote `context/auth.md`: where keys live, how to save one, and that saving a
  key is a secrets-file edit, not a repo commit.

Verified: all eight files compile; fallback tested against openclaw-only,
hermes-present, and neither-present homes.

## Completed the OpenClaw -> Hermes migration in code

Ben's follow-up: the migration was supposed to be done, but things were broken.
Confirmed why — commit `b8a6c99` (Jul 28) changed only prose. Every executable
path still pointed at the old layout.

**Fix (commit `355be8f`):** three resolvers, everything routed through them.

- `lib/paths.py` — workspace/logs/memory/scripts/agent-home/gateway-unit.
  Derives from the checkout, so it is correct at `/root/.openclaw/workspace`,
  `/root/clawd`, or anywhere else. Agent home tries Hermes then legacy.
- `lib/env.py` — one secrets loader, honours `HERMES_HOME`. Replaced the seven
  divergent inline `_load_env()` copies.
- `lib/gateway.py` — `hermes gateway` CLI first, systemd fallback.

96 files: 40+ scripts, both watchdogs, the four production workflow scripts
(meeting-wrap, morning-scan, fam-sync x2), skills, shell entrypoints,
setup-cron.sh, logrotate, and the workspace-os backend.

Env overrides: `CORTANA_WORKSPACE`, `CORTANA_LOGS`, `CORTANA_MEMORY_DB`,
`CORTANA_GATEWAY_SERVICE`, `HERMES_HOME`.

Also fixed a pre-existing `SyntaxError` in `scripts/cortana-x-oauth-setup.py` —
the X OAuth refresh script `TOOLS.md` documents had never been runnable.
